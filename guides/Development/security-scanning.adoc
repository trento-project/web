= Security scanning

Trento runs static analysis and dependency scanning in the
`Security Scanning` workflow (`.github/workflows/security.yaml`). Reports are
published as SARIF, both as workflow artifacts and to the repository's
Security -> Code scanning tab.

None of these checks block a merge. They establish a baseline that is triaged
before any single tool is switched to blocking.

== Running the scanners locally

=== Sobelow (Elixir static analysis)

[source,bash]
----
mix sobelow --format sarif --out /tmp/sobelow.sarif
jq '.runs[0].results | length' /tmp/sobelow.sarif
----

For readable output while working, drop the SARIF flags:

[source,bash]
----
mix sobelow
----

=== OSV-Scanner (dependency vulnerabilities)

[source,bash]
----
docker run --rm -v "$PWD:/src" -w /src ghcr.io/google/osv-scanner:v2.5.0 \
  scan source --lockfile mix.lock --lockfile assets/package-lock.json
----

=== ESLint security rules (JavaScript)

The security rules live in `assets/eslint.security.config.mjs`, a separate flat
config that layers `eslint-plugin-security` and `eslint-plugin-no-unsanitized`
over the base config. Keeping them out of `eslint.config.mjs` means the
`npm run lint` gate in `ci.yaml` does not start failing on pre-existing findings.

[source,bash]
----
cd assets && npm run lint:security
----

To reproduce exactly what CI publishes, including the suppression filter:

[source,bash]
----
cd assets && SARIF_ESLINT_IGNORE_SUPPRESSED=true npx eslint . \
  --config eslint.security.config.mjs \
  -f @microsoft/eslint-formatter-sarif \
  -o /tmp/eslint.sarif
----

=== CodeQL (JavaScript and GitHub Actions)

CodeQL runs in CI only; it needs the CodeQL CLI and a downloaded query pack, so
there is no lightweight local equivalent. Two packs run as a matrix:
`javascript-typescript` and `actions`. Paths excluded from analysis are listed
in `.github/codeql/config.yml`.

The `actions` pack is included because the workflows here use labeled triggers
and consume secrets. It flags missing workflow `permissions:` blocks, untrusted
checkout, cache poisoning and secret exposure. Every one of the 52 findings it
reports today is `actions/missing-workflow-permissions`.

On a pull request CodeQL runs in diff-informed mode: it builds the full
database but only reports alerts for code the pull request changes, so a pull
request that touches no JavaScript shows a CodeQL count of zero even when the
codebase has findings. The complete set appears on the nightly run and on
pushes to `main`. To see it for a branch before merging, dispatch the workflow
manually, which is not a pull request event and so analyses everything:

[source,bash]
----
gh workflow run security.yaml --ref "$(git branch --show-current)"
----

== Suppressing a finding

Every suppression needs a stated reason in the pull request that adds it.

Sobelow:: Add `# sobelow_skip ["Module.Check"]` immediately above the function,
or add the finding to the `ignore` list in `.sobelow-conf` when it applies
project-wide.

OSV-Scanner:: There is no in-repo suppression. Either upgrade the dependency or
dismiss the alert in the Security tab with a reason.

ESLint:: Add an `// eslint-disable-next-line <rule>` comment with the reason on
the line above. The CI job sets `SARIF_ESLINT_IGNORE_SUPPRESSED=true`, so
suppressed findings are never uploaded. Note that this stops the finding being
reported on future runs; it does not dismiss an alert already filed. Dismiss
that one in the Security tab.

CodeQL:: Dismiss the alert in the Security tab. Inline suppression comments are
not supported for the query packs in use here.

Code scanning generally:: Dismissing an alert in the Security tab records the
reason and applies to future runs.

== Known gaps

* Dependencies sourced from git rather than Hex (`langchain`, `gen_rmq`,
  `trento_contracts`) resolve to commit SHAs in `mix.lock`, so they are not
  matched against Hex advisories.
* Container base images are not scanned.
* Secrets are not scanned.
* The ESLint security rules apply to `.js` and `.jsx` only, and cover `assets/`
  alone, since the job runs `eslint` from that directory. `test/e2e` is
  therefore CodeQL-only.
* `assets/vendor` is excluded from both scanners: CodeQL skips it via
  `paths-ignore`, and `assets/vendor/topbar.js` carries a blanket
  `eslint-disable`. Nothing scans it.
* CodeQL's `paths-ignore` excludes `*.test.js`, `*.test.jsx`, `*.stories.js`
  and `*.stories.jsx`, but not `*.spec.*`, `__tests__/`, `test-utils/` or
  `test/e2e/cypress/**`, so most test code is still analysed.
